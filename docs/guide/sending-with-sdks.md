# Sending with SDKs

Thinpost accepts mail on routes shaped like four hosted providers' send APIs. You keep your application code and change the SDK's host and credential. Thinpost does not implement every provider feature; this page covers what to configure and what differs. The full field-by-field matrix is in [Provider compatibility](/reference/compatibility/).

::: warning Subset, not parity
Each adapter accepts a documented subset of the provider's request fields and rejects the rest with a 400 instead of ignoring them. Test your own payloads before you switch.
:::

## Before you send

For any provider:

1. An administrator has created an **app** and issued an **API key** for it ([Concepts](/guide/concepts)).
2. The `From` domain is a **verified sender domain** of that app ([Sender domains](/guide/domains)). For Mailgun, the domain in the URL path must be authorized too.
3. The app has **limits set**. A new app has a daily recipient limit, a pending-message limit and an upload rate of zero, which blocks submission until an administrator raises them. Requests over a limit get HTTP 429.
4. Your SDK points at Thinpost over **HTTPS**.

## Tested SDKs

An automated contract suite runs the official Node SDKs against the real HTTP adapters.

| Provider | Package and tested version | Operations tested | Route |
| --- | --- | --- | --- |
| Postmark | `postmark` 5.1.0 | `sendEmail`, `sendEmailBatch` | `POST /email`, `POST /email/batch` |
| Resend | `resend` 6.37.0 | `emails.send`, `batch.send` | `POST /emails`, `POST /emails/batch` |
| SendGrid | `@sendgrid/mail` 8.1.6 | `send` with one or more personalizations, `sendMultiple` | `POST /v3/mail/send` |
| Mailgun | `mailgun.js` 14.1.0 | `messages.create` | `POST /v3/{domain}/messages` |

Other languages and versions that speak the same HTTP shapes should work for the supported fields, but they are not part of the suite.

## Point the SDK at Thinpost

Use your Thinpost origin, shown here as `mail.example.com`, and the app key as the credential.

::: code-group

```js [Postmark]
import { ServerClient } from "postmark";

const client = new ServerClient("<app key>", {
  requestHost: "mail.example.com",
  useHttps: true,
});

await client.sendEmail({
  From: "hello@example.com",
  To: "user@example.net",
  Subject: "Welcome",
  HtmlBody: "<p>Hello.</p>",
  TextBody: "Hello.",
});
```

```js [Resend]
import { Resend } from "resend";

const resend = new Resend("<app key>", {
  baseUrl: "https://mail.example.com",
});

await resend.emails.send({
  from: "hello@example.com",
  to: "user@example.net",
  subject: "Welcome",
  html: "<p>Hello.</p>",
});
```

```js [SendGrid]
import sgMail from "@sendgrid/mail";

sgMail.setApiKey("<app key>");
sgMail.setDefaultRequest("baseUrl", "https://mail.example.com");

await sgMail.send({
  from: "hello@example.com",
  to: "user@example.net",
  subject: "Welcome",
  html: "<p>Hello.</p>",
});
```

```js [Mailgun]
import formData from "form-data";
import Mailgun from "mailgun.js";

const mg = new Mailgun(formData).client({
  username: "api",
  key: "<app key>",
  url: "https://mail.example.com",
});

await mg.messages.create("example.com", {
  from: "hello@example.com",
  to: "user@example.net",
  subject: "Welcome",
  html: "<p>Hello.</p>",
});
```

:::

The SendGrid SDK warns when a key does not start with `SG.`. Thinpost keys do not; the warning is harmless and the request is still sent.

## Authentication

| Provider | Credential |
| --- | --- |
| Postmark | App key in the `X-Postmark-Server-Token` header |
| Resend | `Authorization: Bearer <app key>` |
| SendGrid | `Authorization: Bearer <app key>` |
| Mailgun | HTTP Basic, user `api`, password `<app key>` |

A missing, wrong or revoked key is 401. A key authorizes only its own app.

## What a request can carry

All four adapters accept:

- `From`, `To`, `Cc`, `Bcc`, `Subject`, plain-text and HTML bodies, and reply addresses.
- **Attachments**, including inline images, with at most 20 files per message. Content is base64 in the JSON adapters and multipart parts for Mailgun. Remote attachment URLs are rejected. The total decoded size is bounded by `THINPOST_MAX_ATTACHMENT_BYTES` (5 MiB by default, at most 5.5 MiB).
- A few **custom headers**: `Reply-To`, `In-Reply-To`, `References`, and your own `List-Unsubscribe` and `List-Unsubscribe-Post`. Any other custom header is rejected. `Message-ID` is always generated by Thinpost.

Request size is limited to 2 MiB, except single-message requests, which may be larger to fit attachments. At most 100 recipients per message. A Postmark or Resend batch holds at most 100 messages and 2 MiB in total.

Each To, Cc and Bcc recipient is a separate delivery. Every copy carries one `To` header listing every To address (and one `Cc` header when there are Cc addresses), and never a `Bcc` header. To hide recipients from each other, send separate messages.

### Templates and unsupported features

Thinpost has no templates, no SendGrid substitution tags and no SendGrid webhooks. Requests that use fields outside the supported subset fail with the provider's normal invalid-request error and do not echo the value.

## Message IDs

The submission response returns the message ID in the provider's shape: UUID text for Postmark `MessageID` and Resend `id`, and `<id@from-domain>` for Mailgun `id`. SendGrid returns no body. It returns an `X-Message-Id` header only when the request produced exactly one message.

All of them carry the same 128 bits as the console's 32-character ID. Console search and the admin API accept every form. Native webhooks use the 32-hex form: remove hyphens from UUID text, or strip `<`, `>` and `@domain`. If you use a provider's webhook format, the ID matches what the SDK returned with no conversion.

The RFC 5322 `Message-ID` header is `<{message id}@{sender domain}>`, so you can compute it from the response and use it for `In-Reply-To` and `References` when replying to the same thread.

## Idempotency and retries

- **Resend** honors `Idempotency-Key`, scoped to the app and adapter, for 24 hours. For a batch the key identifies the whole ordered batch.
- **Postmark, SendGrid and Mailgun** have no idempotency key here. If a request's outcome is ambiguous (a timeout, for instance), retrying can send a duplicate. A Postmark batch can be partially committed.
- A response means the message is committed and queued. It does not mean it was delivered. Use [webhooks](/guide/webhooks) or the message history for outcomes.

## Thinpost extensions

These are not provider features. They are optional.

### Enhanced Protection

Send `X-Thinpost-Enhanced-Protection: true` to require validated TLS on every attempt and to protect the message in the console ([Concepts](/guide/concepts#enhanced-protection)). Where each SDK lets you set a header, set it per message. Postmark and SendGrid take it as an HTTP header on the request; Resend can supply it in request options; Mailgun can use `o:require-tls` instead. A client-wide header applies to every message sent through that client.

### Tracking per message

Open and click tracking are off unless an app default or the message turns them on. Explicit per-message values always win over the app default. See [Open and click tracking](/guide/tracking).

| Provider | Opens | Clicks |
| --- | --- | --- |
| Postmark | `TrackOpens` | `TrackLinks`: `HtmlOnly` (`None` opts out) |
| Resend | `X-Thinpost-Track-Opens: true` header | `X-Thinpost-Track-Clicks: true` header |
| SendGrid | `tracking_settings.open_tracking.enable` | `tracking_settings.click_tracking.enable` with `enable_text: false` |
| Mailgun | `o:tracking-opens=yes` | `o:tracking-clicks=htmlonly` |

Tracking applies to HTML bodies only.

## Reading messages back

An app key can also read back its own messages through `GET /app/v1/messages/{id}` and its `/body` and `/attachments/{index}` sub-routes. These are Thinpost routes, not a provider API, and are described in the [App API reference](/reference/api/app).
