# Generated code

Two things are generated. Neither is edited by hand.

| Output | Source | Committed | Command |
| --- | --- | --- | --- |
| Control protocol Go code in `api/control/v1/` | `api/control/v1/control.proto` | Yes | `sh scripts/gen-proto.sh` |
| The console's TypeScript API client in `ui/src/openapi-client-generated/` | `api/admin/openapi.yaml` | No | `npm run gen` in `ui/` |

## Control protocol

`scripts/gen-proto.sh` regenerates the Go message and gRPC code from `api/control/v1/control.proto`. It is pinned to the generator versions recorded in the headers of the generated files:

| Tool | Version |
| --- | --- |
| `protoc` (libprotoc) | 36.2 |
| `protoc-gen-go` | v1.36.12 |
| `protoc-gen-go-grpc` | 1.6.2 |

Install the pinned tools, then run the script from anywhere in the repository:

```sh
go install google.golang.org/protobuf/cmd/protoc-gen-go@v1.36.12
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@v1.6.2
# protoc 36.2: download the release for your platform and put it on PATH
sh scripts/gen-proto.sh
```

The script runs `protoc` with `paths=source_relative`, so output lands next to the `.proto` file. CI regenerates the code and fails on any difference under `api/control`, so commit the regenerated files with your `.proto` change. A different tool version changes the generated headers and code, so use the pinned versions.

A change to the protocol is a wire change. The control plane and the edge must speak the same protocol version, and a mixed-version rolling upgrade across protocol versions is not supported. Bump the version deliberately, and see [Control protocol](/reference/control-protocol).

## Operator API client

The OpenAPI contracts are hand-written and are the source of truth:

- `api/admin/openapi.yaml` is the operator API that the console uses.
- `api/app/openapi.yaml` is the app API (message reads, and release or cancel of held messages).

The console client is generated from the admin contract by `@zyno-io/openapi-client-codegen` through `ui/openapi-specs.json`, which maps the spec to `src/openapi-client-generated`. It is git-ignored and regenerated by `npm run gen`, and automatically by `npm test`, `npm run typecheck` and `npm run build`. The control image's console build also generates it from the checked-in contract, never from the build context.

Rules:

- Change the OpenAPI file first, and keep it truthful. This site renders the same files in the [API reference](/reference/openapi).
- Never commit generated client files.
- Keep `operationId` values stable. The console calls operations by those names.
